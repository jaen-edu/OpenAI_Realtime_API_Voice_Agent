# 9교시 — 토글 #2(계산기) + 가드레일 (모델 입력을 믿지 않기)

> **이 교시가 끝나면** 에이전트에 계산 도구가 하나 더 붙고, 무엇보다 **모델이 보낸 함수 인자를 그대로 실행하지 않고 검증·안전 실행하는 가드레일**이 생깁니다. 8교시의 함수 호출 왕복은 그대로 두고, 그 사이에 "이 요청을 실행해도 되는가?"를 판단하는 문지기를 세웁니다.

---

## 0. 이 교시에 만드는 것 (한눈에)

8교시에서 모델은 우리가 준 도구를 부를 수 있게 됐습니다. 그런데 모델이 보내는 **함수 인자는 우리가 통제하지 못하는 입력**입니다. 이상한 값이 올 수도, 위험한 요청이 올 수도 있습니다. 이 교시에는 실행 **직전에** 그 인자를 검사하는 층을 넣습니다.

```
모델: function_call_arguments.done  (name, arguments)
   → 🛡️ 가드레일: 인자가 규칙에 맞는가? 안전한가?
        ├─ OK   → 실제 도구 실행 → 결과 반환
        └─ 위반 → 실행하지 않고, 에러 결과를 모델에 돌려줌
```

새 도구로는 **계산기 `calculate`**를 넣습니다. 계산기는 가드레일이 왜 필요한지 가장 분명히 보여줍니다 — 모델이 보낸 수식을 아무 검증 없이 실행하면 **코드가 주입**될 수 있기 때문입니다.

> ⚠️ **핵심 원칙**: 모델의 출력(함수 인자 포함)은 **신뢰 경계 바깥**의 입력으로 취급합니다. 사용자 입력을 검증하듯, 모델 입력도 검증합니다.

---

## 🧭 잠깐, 배경지식

이 교시의 핵심인 **가드레일(guardrail)**을 짚습니다.

**① 신뢰 경계(trust boundary).** 프로그램에는 "여기서부터는 못 믿는 데이터"라는 경계가 있습니다. 사용자가 타이핑한 값, 네트워크로 온 값이 대표적입니다. 모델이 만든 함수 인자도 여기에 속합니다 — 모델은 대체로 합리적이지만, 틀린 값·비어 있는 값·악의적으로 유도된 값을 보낼 수 있습니다.

**② 가드레일 = 실행 전 검문소.** 가드레일은 "이 요청을 그대로 실행해도 되는가"를 실행 **직전에** 판단하는 장치입니다. 규칙에 맞지 않으면 실행을 막고 안전하게 거부합니다. 공항 검색대처럼, 통과 기준을 못 넘으면 들여보내지 않습니다.

**③ `eval`은 왜 위험한가(코드 주입).** 파이썬의 `eval("2+3")`은 문자열을 **코드로 실행**합니다. 편해 보이지만, `eval`에 임의 문자열을 넘기면 `eval("__import__('os').system('rm ...')")`처럼 **원치 않는 코드가 실행**될 수 있습니다. 이것이 코드 주입(injection)입니다. 모델이 준 수식을 `eval`로 처리하면 이 문에 무방비가 됩니다.

**④ 화이트리스트(whitelist) 방식.** 안전한 대안은 "허용한 것만 통과"입니다. 계산기라면 숫자와 사칙연산 같은 **미리 정한 연산만** 허용하고, 나머지(함수 호출·이름·속성 접근)는 전부 거부합니다. "위험한 걸 막자(블랙리스트)"보다 "안전한 것만 허용(화이트리스트)"가 훨씬 튼튼합니다.

**⑤ 가드레일은 여러 겹.** 이 교시에서는 두 겹을 만듭니다. (1) **인자 검증** — 필수 인자가 있는지 등 도메인 규칙 확인. (2) **안전 실행** — 계산기가 `eval` 대신 화이트리스트 파서를 쓰기. 둘 다 "함부로 실행하지 않기"라는 같은 목표를 향합니다.

> 💡 아래 개념에서 "안전한 수식 계산"을 코드 흐름으로 이어서 봅니다.

---

## 1. 개념 빠르게 잡기

### 안전한 수식 계산 — `ast`로 화이트리스트

> 파이썬 표준 라이브러리 `ast`(Abstract Syntax Tree, 추상 구문 트리)는 코드를 **실행하지 않고 구조로만** 분석합니다. `"3 + 4 * 2"`를 파싱하면 "덧셈(3, 곱셈(4, 2))" 같은 트리가 됩니다. 우리는 이 트리를 훑으며 **숫자·사칙연산 노드만 허용**하고, 함수 호출·이름 같은 노드를 만나면 거부합니다. 그래서 계산은 되지만 코드는 못 심습니다.

### 두 겹의 가드레일

> | 가드레일 | 계층 | 하는 일 |
> |---|---|---|
> | 인자 검증(`check_required`) | 도메인 | 명세가 요구하는 인자가 실제로 왔는지 확인 |
> | 안전 실행(`safe_calculate`) | 어댑터 | 수식을 `eval` 없이 화이트리스트로 계산 |

### 실행 진입점은 그대로 `run_tool`

> 8교시의 `run_tool(name, arguments)`는 그대로 씁니다. 다만 그 안에서 **먼저 가드레일을 통과**시키고, 통과한 것만 실제 함수로 넘깁니다. 핸들러(인프라)는 바뀌지 않습니다 — 문지기를 진입점 안쪽에 세우기 때문입니다.

```python
import ast          # 코드를 '실행하지 않고' 구조(트리)로 분석하는 표준 라이브러리
import operator     # +, -, * 등을 실제 파이썬 연산으로 이어주는 표준 라이브러리

# 허용할 '이항 연산'(둘을 계산): 노드 타입 → 실제 연산 함수.
_BIN_OPS = {
    ast.Add: operator.add,        # +
    ast.Sub: operator.sub,        # -
    ast.Mult: operator.mul,       # *
    ast.Div: operator.truediv,    # /
    ast.Mod: operator.mod,        # %
    ast.Pow: operator.pow,        # **
}
# 허용할 '단항 연산'(하나에 적용): 음수(-x), 양수(+x).
_UNARY_OPS = {
    ast.UAdd: operator.pos,
    ast.USub: operator.neg,
}


def safe_calculate(expression: str) -> float:
    """수식 문자열을 eval 없이 계산한다. 허용되지 않은 식이면 ValueError."""
    try:
        # mode="eval": '식(expression)' 하나로 파싱. .body가 그 식의 최상위 노드.
        tree = ast.parse(expression, mode="eval").body
    except SyntaxError as exc:
        # 문법이 깨진 입력도 조용히 ValueError로 통일(밖에서 한 번에 처리).
        raise ValueError(f"수식을 해석할 수 없습니다: {expression}") from exc
    return _eval_node(tree)


def _eval_node(node: ast.AST) -> float:
    """트리 노드 하나를 재귀로 계산한다. 허용 목록에 없으면 거부."""
    # 1) 숫자 상수(3, 4.5 등)는 그대로 값.
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    # 2) 이항 연산(a + b): 좌·우를 각각 계산해 연산자로 합친다.
    if isinstance(node, ast.BinOp) and type(node.op) in _BIN_OPS:
        left = _eval_node(node.left)         # 왼쪽 가지 계산(재귀)
        right = _eval_node(node.right)       # 오른쪽 가지 계산(재귀)
        return _BIN_OPS[type(node.op)](left, right)
    # 3) 단항 연산(-a): 안쪽을 계산해 부호를 적용.
    if isinstance(node, ast.UnaryOp) and type(node.op) in _UNARY_OPS:
        return _UNARY_OPS[type(node.op)](_eval_node(node.operand))
    # 4) 그 외(이름·함수 호출·속성 접근 등)는 전부 거부 — 이것이 화이트리스트의 핵심.
    raise ValueError("허용되지 않은 식입니다(숫자와 사칙연산만 가능).")
```

> 💡 **왜 `eval`을 안 쓰나?** `eval("__import__('os').system('...')")`는 실제로 시스템 명령을 실행합니다. 위 방식은 트리에서 **숫자와 사칙연산 노드만** 값으로 바꾸고, 함수 호출(`Call`)·이름(`Name`) 노드를 만나면 4번에서 거부합니다. 그래서 계산은 되고 코드 주입은 막힙니다.

def calculate(expression: str) -> str:

```python
def run_tool(name: str, arguments: dict) -> str:
    """이름으로 함수를 찾아 실행하고 결과를 JSON 문자열로. 실패해도 안전하게 반환."""
    handler = TOOL_HANDLERS.get(name)
    if handler is None:
        return json.dumps({"error": f"unknown tool: {name}"}, ensure_ascii=False)
    try:
        result = handler(**arguments)                    # 실제 실행
    except (ValueError, TypeError) as exc:               # 검증 실패·잘못된 인자 등
        # 예외로 루프가 죽지 않게, 에러를 결과로 감싸 모델에 돌려준다.
        return json.dumps({"error": str(exc)}, ensure_ascii=False)
    return json.dumps({"result": result}, ensure_ascii=False)
```

```python
from voice_agent.domain.tool_spec import ToolSpec   # 검사 기준이 되는 명세


def check_required(spec: ToolSpec, arguments: dict) -> list[str]:
    """명세가 요구하는 인자가 arguments에 '있고 비어 있지 않은지' 검사한다.

    문제가 없으면 빈 목록, 있으면 사람이 읽는 오류 메시지 목록을 돌려준다.
    """
    errors: list[str] = []
    # 명세의 parameters에 적힌 인자 이름들을 하나씩 확인한다.
    for name in spec.parameters:
        value = arguments.get(name)                 # 넘어온 값(없으면 None)
        # None 이거나, 문자열인데 공백만 있으면 '빠졌다'고 본다.
        if value is None or (isinstance(value, str) and not value.strip()):
            errors.append(f"필수 인자 누락: {name}")
    return errors
```

from voice_agent.domain.tool_guard import check_required   # 파일 위쪽 import에 추가


def run_tool(name: str, arguments: dict) -> str:
    handler = TOOL_HANDLERS.get(name)
    if handler is None:
        return json.dumps({"error": f"unknown tool: {name}"}, ensure_ascii=False)

    # 🛡️ 가드레일: 실행 전에 필수 인자를 검증한다.
    spec = _SPEC_BY_NAME.get(name)
    if spec is not None:
        errors = check_required(spec, arguments)
        if errors:                                       # 하나라도 위반이면
            return json.dumps({"error": "; ".join(errors)}, ensure_ascii=False)

    try:
        result = handler(**arguments)
    except (ValueError, TypeError) as exc:
        return json.dumps({"error": str(exc)}, ensure_ascii=False)
    return json.dumps({"result": result}, ensure_ascii=False)
```

```

**예상 출력** (🟢): 기존 + 새 1개 모두 `passed`

> 💡 **순서가 핵심**: 검증 → (통과 시) 실행. 문지기를 실행 앞에 세웠기 때문에, 잘못된 요청은 도구 함수에 **닿지도 않습니다.** 이렇게 하면 각 도구 함수는 "올바른 입력만 온다"는 전제로 단순하게 짤 수 있습니다.

## 📖 용어 사전 (이 교시 신규)

- **가드레일(guardrail)**: 실행 전에 요청이 규칙·안전 기준에 맞는지 검사해 걸러내는 장치.
- **신뢰 경계(trust boundary)**: "여기서부터는 못 믿는 데이터"라는 경계. 모델 출력도 이 바깥.
- **코드 주입(injection)**: 데이터인 척 넘긴 문자열이 코드로 실행되어 악용되는 취약점.
- **`eval`**: 문자열을 코드로 실행하는 파이썬 함수. 신뢰 못 할 입력에 쓰면 위험.
- **화이트리스트(whitelist)**: "허용한 것만 통과"시키는 방어 방식(블랙리스트보다 튼튼).
- **`ast`(Abstract Syntax Tree, 추상 구문 트리)**: 코드를 실행하지 않고 구조(트리)로 분석하는 표준 라이브러리.
- **인자 검증(argument validation)**: 함수에 넘길 인자가 규칙에 맞는지 실행 전에 확인.
- **폴백(fallback)**: 실패했을 때 대신 쓰는 안전한 대안 동작.
