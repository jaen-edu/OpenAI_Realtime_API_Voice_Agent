# 8교시 — 도구(함수 호출) 붙이기 + 토글 #1 (날씨/시간)

> **이 교시가 끝나면** 에이전트가 "지금 몇 시야?", "서울 날씨 어때?" 같은 질문에 **지어내지 않고 실제 도구를 호출해** 답합니다. 모델이 도구를 부르면(함수 호출) 우리가 코드를 실행해 결과를 돌려주고, 모델이 그 결과를 말로 풀어냅니다. 3교시에서 만든 `ToolRegistryPort`·`ListActiveTools`와 토글이 여기서 실제로 쓰입니다.

---

## 0. 이 교시에 만드는 것 (한눈에)

지금까지의 에이전트는 시간·날씨·경기 결과를 물으면 **그럴듯하게 지어냈습니다**(할루시네이션). 모델은 "지금 이 순간"의 사실을 알 수 없기 때문입니다. 이 교시에는 모델에게 **도구(함수)**를 쥐여줘, 필요할 때 우리 코드를 부르게 만듭니다.

```
사용자: "지금 몇 시야?"
   → 모델: (session.update로 받은 도구 목록에서 get_current_time을 골라)
        response.function_call_arguments.done  ← "이 함수를 이 인자로 실행해줘"
   → 우리: get_current_time() 실행 → "오후 3시 12분"
        conversation.item.create (function_call_output)  ← 결과를 모델에 돌려줌
        response.create                                   ← "이제 이 결과로 답해줘"
   → 모델: "지금은 오후 3시 12분이에요."  ← 지어내지 않은 진짜 답
```

> ⚠️ **핵심 구분**: 모델은 함수를 **직접 실행하지 않습니다.** "이 함수를 이 인자로 불러 달라"고 **요청만** 합니다. 실제 실행은 우리(서버 코드)가 하고, 결과를 다시 모델에 넘깁니다. 그래서 날씨·DB·사내 API 등 **무엇이든** 도구로 붙일 수 있습니다.

## 🧭 잠깐, 배경지식

이 교시의 핵심인 **함수 호출(function calling)**을 짚습니다.

**① 도구(tool) / 함수 호출(function calling).** 모델에게 "네가 쓸 수 있는 함수 목록"을 미리 알려두면, 모델은 질문에 답하기 위해 그중 하나가 필요하다고 판단할 때 **그 함수를 지목**합니다. 이것이 함수 호출입니다. 모델은 코드를 실행할 능력이 없으므로, "실행해 달라"는 **주문서**만 내밀고 실제 실행은 우리가 합니다.

**② 왜 필요한가.** 모델의 지식은 학습 시점에 멈춰 있고, "지금 몇 시", "오늘 서울 날씨" 같은 **실시간·외부 사실**은 알 수 없습니다. 모르면서도 그럴듯하게 지어내는 게 할루시네이션입니다. 도구를 주면 모델은 지어내는 대신 **실제 데이터를 가져와** 답합니다.

**③ JSON 스키마(JSON Schema)로 함수를 설명한다.** 모델에게 함수를 알려줄 때는 이름·설명·**입력 형식**을 JSON 스키마(데이터의 모양을 정하는 표준 규격)로 적습니다. 예를 들어 "`get_weather`는 `city`라는 문자열 하나를 받는다"처럼요. 모델은 이 설명을 보고 언제·어떤 인자로 부를지 판단합니다.

**④ 왕복(round-trip) 한 번 더.** 지금까지는 "사용자 발화 → 응답" 한 번이었지만, 함수 호출이 끼면 그 사이에 **"모델의 함수 요청 → 우리 실행 → 결과 반환 → 모델의 최종 응답"**이라는 왕복이 한 번 더 생깁니다. 이 왕복을 이벤트로 엮는 게 이 교시의 일입니다.

**⑤ 토글(toggle)로 켜고 끄기.** 도구를 항상 다 켜둘 필요는 없습니다. 3교시에서 만든 `ToolToggleState`로 **켜진 도구만** 골라 모델에게 넘깁니다. 그래서 "날씨만 켜기", "시간·날씨 둘 다 켜기"를 자유롭게 바꿀 수 있습니다.

> 💡 아래 "1. 개념 빠르게 잡기"에서 이 흐름을 이벤트 이름과 함께 이어서 봅니다.

## 1. 개념 빠르게 잡기

### 함수 호출에 쓰는 이벤트

| 방향 | 이벤트 | 의미 |
|---|---|---|
| 보냄 | `session.update`의 `tools` | 모델에게 "쓸 수 있는 함수 목록"을 알려준다 |
| 보냄 | `session.update`의 `tool_choice` | 도구를 언제 쓸지 정책(`"auto"`=모델이 알아서) |
| 받음 | `response.function_call_arguments.done` | 모델이 "이 함수를 이 인자로 실행해줘"라고 요청 (call_id·name·arguments) |
| 보냄 | `conversation.item.create` (`function_call_output`) | 실행 결과를 모델에 돌려준다 (같은 call_id로) |
| 보냄 | `response.create` | "이제 이 결과로 최종 응답을 만들어줘" |

> 💡 **`response.function_call_arguments.done` 하나면 충분.** 인자가 조각(`...delta`)으로도 오지만, `done` 이벤트가 **완성된 인자 전체**(JSON 문자열)와 `call_id`·`name`을 한꺼번에 주므로, 우리는 이 이벤트만 보면 됩니다.

### `call_id` — 요청과 결과를 잇는 실

> 모델의 함수 요청에는 `call_id`가 붙어 있습니다. 결과를 돌려줄 때 **같은 `call_id`**를 실어야, 서버가 "아, 아까 그 요청의 답이구나" 하고 이어붙입니다. 영수증 번호 같은 것입니다.

### 계층 배치 (Clean Architecture)

> - **도메인**: `ToolSpec`(도구 명세), `ToolToggleState`(토글) — 2교시.
> - **유즈케이스**: `ListActiveTools`(켜진 도구만 필터) — 3교시.
> - **어댑터**: 도구 명세를 Realtime JSON으로 변환, 함수 호출 이벤트 판정, 실제 도구 실행.
> - **인프라(핸들러)**: 이벤트 흐름을 엮어 실행을 지휘.

## STEP 1 — 🔴🟢 실제 도구 함수 (TDD)

먼저 모델이 부를 **진짜 함수** 두 개를 만듭니다. `get_current_time`은 실제 시각을, `get_weather`는 데모용 날씨를 돌려줍니다. (날씨는 실제 API 대신 고정 데이터를 씁니다. 뒤에서 실제 API로 바꾸는 법을 안내합니다.)

```python
import json

from voice_agent.adapter.tools import get_current_time, get_weather, run_tool


def test_get_current_time_returns_string():
    # 시각 함수는 사람이 읽을 수 있는 문자열을 돌려준다(정확한 값은 실행 시각마다 다름).
    out = get_current_time()
    assert isinstance(out, str)
    assert len(out) > 0


def test_get_weather_returns_city_info():
    # 데모 날씨는 도시 이름을 담은 설명 문자열을 돌려준다.
    out = get_weather(city="서울")
    assert "서울" in out


def test_run_tool_dispatches_by_name():
    # run_tool은 이름으로 함수를 찾아 실행하고, 결과를 'JSON 문자열'로 돌려준다.
    #  (모델에 돌려줄 function_call_output이 JSON 문자열이어야 하기 때문)
    out = run_tool("get_weather", {"city": "부산"})
    parsed = json.loads(out)          # 문자열을 다시 dict로 되돌려 확인
    assert "부산" in parsed["result"]


def test_run_tool_unknown_name_is_safe():
    # 등록 안 된 이름이 와도 죽지 않고, 에러를 담은 JSON을 돌려준다.
    out = run_tool("no_such_tool", {})
    parsed = json.loads(out)
    assert "error" in parsed
```

```python
import json                                  # 결과를 JSON 문자열로 만들기 위해
from datetime import datetime                # 실제 현재 시각을 얻기 위해

from voice_agent.domain.tool_spec import ToolSpec   # 도구 명세(2교시 값객체)


def get_current_time() -> str:
    """지금 시각을 사람이 읽는 문자열로 돌려준다(예: '오후 3시 12분')."""
    now = datetime.now()                     # 실행 순간의 실제 시각
    return now.strftime("%p %I시 %M분")       # %p=오전/오후, %I=12시간제 시, %M=분


def get_weather(city: str) -> str:
    """(데모) 주어진 도시의 날씨를 돌려준다. 실제 API 대신 고정 문구를 쓴다."""
    # 실제 서비스라면 여기서 날씨 API를 호출한다(선택 미션에서 교체).
    return f"{city}의 날씨는 맑고 기온은 22도입니다. (데모 데이터)"


# 이름 → 실제 함수 로 이어주는 표. run_tool이 여기서 함수를 찾아 부른다.
TOOL_HANDLERS = {
    "get_current_time": get_current_time,
    "get_weather": get_weather,
}


# 모델에게 알려줄 '도구 명세' 목록. name/description/parameters로 구성.
#  - description: 모델이 '언제 이 도구를 쓸지' 판단하는 근거.
#  - parameters: 입력 형식(여기선 property 이름 → 타입).
TOOL_SPECS = [
    ToolSpec(
        name="get_current_time",
        description="현재 시각을 알려준다. 사용자가 지금 몇 시인지 물을 때 사용.",
        parameters={},                       # 입력 없음
    ),
    ToolSpec(
        name="get_weather",
        description="특정 도시의 현재 날씨를 알려준다. 날씨를 물을 때 사용.",
        parameters={"city": {"type": "string"}},   # city: 문자열 하나
    ),
]


def run_tool(name: str, arguments: dict) -> str:
    """이름으로 함수를 찾아 arguments로 실행하고, 결과를 JSON 문자열로 돌려준다."""
    handler = TOOL_HANDLERS.get(name)        # 이름에 해당하는 함수 찾기
    if handler is None:                      # 없으면 에러를 담아 안전하게 반환
        return json.dumps({"error": f"unknown tool: {name}"}, ensure_ascii=False)
    # arguments(dict)를 함수의 키워드 인자로 풀어 호출한다(**arguments).
    #  예: {"city": "부산"} → handler(city="부산")
    result = handler(**arguments)
    # 모델에 돌려줄 결과는 JSON 문자열이어야 하므로 감싼다.
    #  ensure_ascii=False: 한글이 \uXXXX로 깨지지 않게.
    return json.dumps({"result": result}, ensure_ascii=False)
```

## STEP 2 — 🔴🟢 도구 명세 → Realtime JSON 변환 (TDD)

모델에게 도구를 알려주려면, `ToolSpec`을 Realtime가 이해하는 **함수 정의 JSON**으로 바꿔야 합니다. 이 변환은 순수 함수라 테스트가 쉽습니다.

**🔴 테스트** — `tests/adapter/test_realtime_tools.py`

```python
from voice_agent.adapter.realtime_tools import to_realtime_tool, build_tools
from voice_agent.domain.tool_spec import ToolSpec


def test_to_realtime_tool_shape():
    spec = ToolSpec(
        name="get_weather",
        description="날씨를 알려준다",
        parameters={"city": {"type": "string"}},
    )
    tool = to_realtime_tool(spec)

    # Realtime 함수 정의의 표준 모양인지 확인한다.
    assert tool["type"] == "function"
    assert tool["name"] == "get_weather"
    assert tool["description"] == "날씨를 알려준다"
    # parameters는 JSON 스키마(object) 형태로 감싸진다.
    assert tool["parameters"]["type"] == "object"
    assert tool["parameters"]["properties"] == {"city": {"type": "string"}}
    assert tool["parameters"]["required"] == ["city"]   # 인자가 있으면 필수로 표시


def test_build_tools_from_specs():
    specs = [
        ToolSpec(name="get_current_time", description="시각", parameters={}),
        ToolSpec(name="get_weather", description="날씨", parameters={"city": {"type": "string"}}),
    ]
    tools = build_tools(specs)

    assert len(tools) == 2
    assert [t["name"] for t in tools] == ["get_current_time", "get_weather"]
    # 인자 없는 도구는 properties가 비고 required도 빈 목록.
    assert tools[0]["parameters"]["properties"] == {}
    assert tools[0]["parameters"]["required"] == []
```

```python
from voice_agent.domain.tool_spec import ToolSpec   # 변환할 도구 명세


def to_realtime_tool(spec: ToolSpec) -> dict:
    """ToolSpec 하나를 Realtime 함수 정의 JSON(dict)으로 바꾼다."""
    return {
        "type": "function",              # 이 도구가 '함수형'임을 표시
        "name": spec.name,               # 모델이 지목할 함수 이름
        "description": spec.description,  # 모델이 '언제 쓸지' 판단할 설명
        "parameters": {                  # 입력 형식을 JSON 스키마로
            "type": "object",            # 인자들은 object(키-값) 형태
            "properties": spec.parameters,          # 각 인자의 이름·타입
            "required": list(spec.parameters.keys()),  # 정의된 인자는 모두 필수로
        },
    }


def build_tools(specs: list[ToolSpec]) -> list[dict]:
    """도구 명세 목록 전체를 Realtime 함수 정의 목록으로 바꾼다."""
    # 각 spec을 to_realtime_tool로 변환해 리스트로 모은다.
    return [to_realtime_tool(spec) for spec in specs]
```

## STEP 3 — 🔴🟢 함수 호출 이벤트 판정 헬퍼 (TDD)

서버가 보낸 `response.function_call_arguments.done`에서 **함수 이름·call_id·인자**를 뽑는 순수 함수를 만듭니다. (5·6교시의 `extract_transcript_delta` 패턴과 같은 결)

**🔴 테스트** — `tests/adapter/test_function_call.py`

```python
from voice_agent.adapter.function_call import extract_function_call


def test_extracts_function_call():
    # 실제 done 이벤트: name/call_id/arguments(JSON '문자열')를 담고 온다.
    event = {
        "type": "response.function_call_arguments.done",
        "name": "get_weather",
        "call_id": "call_abc",
        "arguments": '{"city": "서울"}',
    }
    fc = extract_function_call(event)

    assert fc is not None
    assert fc["name"] == "get_weather"
    assert fc["call_id"] == "call_abc"
    # arguments 문자열이 dict로 '파싱'되어 나온다.
    assert fc["arguments"] == {"city": "서울"}


def test_returns_none_for_other_events():
    assert extract_function_call({"type": "response.output_audio.delta"}) is None
    assert extract_function_call({"type": "response.done"}) is None


def test_handles_empty_arguments():
    # 인자 없는 함수(get_current_time)는 arguments가 빈 문자열/누락일 수 있다 → 빈 dict.
    event = {
        "type": "response.function_call_arguments.done",
        "name": "get_current_time",
        "call_id": "call_xyz",
        "arguments": "",
    }
    fc = extract_function_call(event)
    assert fc["arguments"] == {}
```

```python
import json   # arguments(JSON 문자열)를 dict로 파싱


def extract_function_call(event: dict) -> dict | None:
    """함수 호출 완료 이벤트면 {name, call_id, arguments(dict)}를, 아니면 None."""
    # 1) 함수 호출 완료 이벤트가 아니면 관심 밖 → None.
    if event.get("type") != "response.function_call_arguments.done":
        return None
    # 2) arguments는 JSON '문자열'. 비어 있으면 빈 dict로 시작.
    raw = event.get("arguments") or ""
    arguments = json.loads(raw) if raw else {}   # 문자열 → dict
    # 3) 실행에 필요한 세 가지를 묶어 돌려준다.
    return {
        "name": event.get("name"),        # 부를 함수 이름
        "call_id": event.get("call_id"),  # 결과를 이어붙일 영수증 번호
        "arguments": arguments,           # 함수에 넘길 인자(dict)
    }
```

## STEP 4 — 🔴🟢 async 세션에 도구 왕복 메서드 추가 (TDD)

5교시 `AsyncRealtimeSession`에 세 가지를 더합니다: (1) `open`이 **도구 목록**도 실을 수 있게, (2) 함수 결과를 돌려주는 `send_tool_result`, (3) 최종 응답을 요청하는 `request_response`.

```python
        # 1) 이름·인자로 실제 도구를 실행한다(결과는 JSON 문자열).
```

## 📖 용어 사전 (이 교시 신규)

- **도구(tool) / 함수 호출(function calling)**: 모델에게 쓸 수 있는 함수 목록을 주고, 필요 시 지목하게 하는 기능.
- **`tools`**: `session.update`에 싣는 함수 정의 목록(모델이 쓸 수 있는 도구).
- **`tool_choice`**: 도구 사용 정책. `"auto"`는 모델이 알아서 판단.
- **JSON 스키마(JSON Schema)**: 데이터(여기선 함수 인자)의 모양을 정하는 표준 규격.
- **`response.function_call_arguments.done`**: 모델이 함수 실행을 요청하며 이름·call_id·인자를 보내는 서버 이벤트.
- **`call_id`**: 함수 요청과 그 결과를 잇는 식별자(영수증 번호).
- **`function_call_output`**: 함수 실행 결과를 모델에 돌려줄 때 쓰는 대화 아이템 타입.
- **`response.create`**: 결과를 받은 뒤 최종 응답 생성을 요청하는 이벤트.
- **할루시네이션(hallucination)**: 모델이 모르는 사실을 그럴듯하게 지어내는 현상.
- **왕복(round-trip)**: 요청과 응답이 오가는 한 번의 순환. 함수 호출은 이 왕복이 한 번 더 생긴다.
- **토글(toggle)**: 도구를 켜고 끄는 상태(`ToolToggleState`).
