# 10교시 — 토글 #3(환율) + 정책 가드레일 (허용 목록 · 빈도 제한)

> **이 교시가 끝나면** 환율 변환 도구가 하나 더 붙고, 가드레일이 **정책 수준**으로 넓어집니다. 9교시가 "형식이 맞는가·안전한가"였다면, 이 교시는 "형식은 맞아도 **허용된 요청인가**", "**너무 자주 부르지는 않는가**"를 판단합니다.

---

## 0. 이 교시에 만드는 것 (한눈에)

9교시의 가드레일은 인자의 **형식**을 봤습니다(누락·위험한 식). 그런데 형식이 완벽해도 막아야 할 요청이 있습니다. 지원하지 않는 통화, 짧은 시간에 쏟아지는 호출 같은 것입니다. 이 교시에는 두 가지 정책 가드레일을 세웁니다.

```
모델: function_call_arguments.done  (name, arguments)
   → 🛡️ 형식 가드레일(9교시): 인자 검증 · 안전 실행
   → 🛡️ 정책 가드레일(이 교시):
        ├─ 허용 목록(allowlist): 지원하는 통화만? (예: KRW·USD·JPY·EUR)
        └─ 빈도 제한(rate limit): 최근 N초 안에 M번 넘게 부르지 않았나?
             ├─ OK   → 실제 도구 실행
             └─ 위반 → 실행하지 않고 안내
```

새 도구는 **환율 변환 `convert_currency`**입니다. 지원 통화가 정해져 있어 **허용 목록**을 자연스럽게 보여 줍니다.

> ⚠️ **형식 vs 정책**: "값이 문자열인가"는 형식 검증, "그 값이 우리가 허용한 통화인가"는 정책 검증입니다. 둘은 다른 층입니다.

---

## 🧭 잠깐, 배경지식

이 교시의 핵심인 **정책 가드레일** 두 종류를 짚습니다.

**① 허용 목록(allowlist).** "미리 정한 것만 통과"시키는 방식입니다(9교시 화이트리스트와 같은 정신). 환율이라면 우리가 데이터를 가진 통화(KRW·USD·JPY·EUR)만 받고, 그 밖의 통화는 거부합니다. 세상 모든 통화를 막는 대신(블랙리스트), **아는 것만 허용**하면 빠짐없이 안전합니다.

**② 빈도 제한(rate limit).** 같은 도구를 짧은 시간에 너무 많이 부르는 것을 막습니다. 왜 필요할까요 — 외부 API 비용, 서버 부하, 오작동 루프(모델이 같은 호출을 반복) 때문입니다. "10초에 5번까지"처럼 **창(window) 안의 호출 수**를 세어 넘으면 잠시 막습니다.

**③ 상태가 있는 가드레일.** 지금까지의 가드레일(인자 검증·안전 실행)은 **입력만 보면 판단**이 끝나는, 상태 없는(stateless) 검사였습니다. 빈도 제한은 다릅니다 — "방금 전에 몇 번 불렀는지"라는 **과거 기록(상태)**을 기억해야 합니다. 그래서 호출 시각들을 모아두고, 오래된 것은 버리며 셉니다.

**④ 테스트하기 좋게 시계를 주입한다.** 빈도 제한은 시간에 의존합니다. 테스트에서 "10초 뒤"를 진짜로 기다릴 수는 없으니, **현재 시각을 알려주는 함수(시계)를 밖에서 주입**합니다(의존성 주입, DI — 3교시). 그러면 테스트가 시계를 마음대로 돌려 빠르고 정확하게 검증할 수 있습니다.

> 💡 아래 개념에서 허용 목록과 빈도 제한이 실행 흐름의 어디에 끼는지 봅니다.

## 1. 개념 빠르게 잡기

### 가드레일이 서는 자리

> ```
> 모델 요청
>   → [형식] check_required (9교시, run_tool 안)
>   → [형식] 안전 실행 safe_calculate (9교시, 도구 안)
>   → [정책] 허용 목록: convert_currency 안에서 지원 통화 확인
>   → [정책] 빈도 제한: RateLimiter (핸들러가 실행 전에 확인)
>   → 통과한 것만 실제 실행
> ```

### 허용 목록은 도구 안에, 빈도 제한은 핸들러에

> - **허용 목록**은 그 도구 고유의 규칙이라 **도구 함수 안**에 둡니다(지원 통화가 아니면 `ValueError` → `run_tool`이 9교시처럼 에러로 감쌈).
> - **빈도 제한**은 "이 세션에서 최근 얼마나 불렀나"라는 상태라, 세션을 쥔 **핸들러(인프라)**가 실행 전에 확인합니다. 판단 로직 자체(`RateLimiter`)는 도메인 순수 규칙으로 빼서 테스트합니다.

# 데모 환율표: '1 USD = 각 통화 값'. 실제 서비스라면 환율 API로 대체한다.
_RATES = {
    "USD": 1.0,
    "KRW": 1400.0,
    "JPY": 150.0,
    "EUR": 0.92,
}

# 허용 목록(allowlist): 우리가 지원하는 통화 집합. 표의 키가 곧 허용 목록이다.
SUPPORTED = set(_RATES.keys())


def convert_currency(amount: float, from_currency: str, to_currency: str) -> float:
    """amount를 from_currency에서 to_currency로 변환한다. 지원 통화가 아니면 ValueError."""
    # 대소문자·공백 차이를 없애 비교(예: ' usd ' → 'USD').
    src = from_currency.strip().upper()
    dst = to_currency.strip().upper()

    # 🛡️ 허용 목록 검사: 둘 중 하나라도 지원 밖이면 거부.
    for code in (src, dst):
        if code not in SUPPORTED:
            raise ValueError(f"지원하지 않는 통화: {code} (지원: {sorted(SUPPORTED)})")

    # USD를 기준으로 환산: from → USD → to.
    #  amount(from) ÷ from레이트 = USD, × to레이트 = to.
    usd = amount / _RATES[src]
    result = usd * _RATES[dst]
    # 소수 둘째 자리로 반올림(금액 표시에 적당).
    return round(result, 2)
```

> 💡 **정규화(normalize) 먼저.** 모델은 `usd`, `USD`, ` Usd `처럼 제각각 보낼 수 있습니다. 비교 전에 `strip().upper()`로 **모양을 통일**하면, 허용 목록 검사가 흔들리지 않습니다. (검증 전 정규화는 흔한 가드레일 습관입니다.)

from voice_agent.domain.rate_limiter import RateLimiter


class FakeClock:
    """테스트용 가짜 시계. tick()으로 시간을 앞으로 돌린다."""
    def __init__(self):
        self.t = 0.0

    def now(self) -> float:
        return self.t

    def tick(self, seconds: float) -> None:
        self.t += seconds


def test_allows_up_to_limit():
    clock = FakeClock()
    limiter = RateLimiter(max_calls=2, window_seconds=10, now=clock.now)

    assert limiter.allow("weather") is True    # 1번째 허용
    assert limiter.allow("weather") is True    # 2번째 허용
    assert limiter.allow("weather") is False   # 3번째는 창 안 초과 → 거부


def test_separate_keys_are_independent():
    clock = FakeClock()
    limiter = RateLimiter(max_calls=1, window_seconds=10, now=clock.now)

    assert limiter.allow("weather") is True
    assert limiter.allow("weather") is False   # weather는 한도 참
    assert limiter.allow("time") is True        # time은 별개로 셈


def test_resets_after_window_passes():
    clock = FakeClock()
    limiter = RateLimiter(max_calls=1, window_seconds=10, now=clock.now)

    assert limiter.allow("weather") is True
    assert limiter.allow("weather") is False
    clock.tick(11)                              # 창(10초)이 지나면
    assert limiter.allow("weather") is True     # 오래된 기록이 빠져 다시 허용
```

**🟢 구현** — `src/voice_agent/domain/rate_limiter.py`

```python
import time                                   # 기본 시계로 쓸 표준 라이브러리
from collections.abc import Callable


class RateLimiter:
    """최근 window_seconds 안에 max_calls번까지만 허용하는 빈도 제한기."""

    def __init__(self, max_calls: int, window_seconds: float,
                 now: Callable[[], float] = time.monotonic):
        # now: '현재 시각'을 주는 함수. 테스트에선 가짜 시계를 주입한다(DI).
        #  기본값 time.monotonic은 뒤로 안 가는(단조 증가) 시계라 측정에 안전.
        self._max = max_calls
        self._window = window_seconds
        self._now = now
        # key(도구 이름) → 호출 시각 목록. 도구마다 따로 센다.
        self._calls: dict[str, list[float]] = {}

    def allow(self, key: str) -> bool:
        """이번 호출을 허용하면 True(그리고 기록), 한도 초과면 False."""
        t = self._now()
        # 이 key의 과거 호출 중, 창(window) 안에 드는 것만 남긴다(오래된 건 버림).
        recent = [c for c in self._calls.get(key, []) if t - c < self._window]
        # 창 안 호출이 이미 한도에 도달했으면 거부(기록은 갱신만 하고 추가 안 함).
        if len(recent) >= self._max:
            self._calls[key] = recent
            return False
        # 아직 여유가 있으면 이번 호출 시각을 남기고 허용.
        recent.append(t)
        self._calls[key] = recent
        return True
```

> 💡 **왜 `time.monotonic`?** 벽시계(`time.time`)는 시스템 시간 보정으로 **뒤로 갈 수** 있어, 경과 시간 측정이 꼬입니다. `monotonic`은 항상 앞으로만 가서 "얼마나 지났나"를 재기에 안전합니다.

## STEP 4 — 🔴🟢 빈도 제한을 실행 전에 확인 (TDD + 결선)

핸들러가 도구를 실행하기 전에 `RateLimiter`에게 물어봅니다. 초과면 실행하지 않고 안내 결과를 돌려줍니다. 판단을 얇은 함수로 빼서 테스트합니다.

**🟢 구현** — `src/voice_agent/adapter/tools.py` 에 추가

```python
from voice_agent.domain.rate_limiter import RateLimiter   # 파일 위쪽 import


def rate_limit_error(limiter: RateLimiter, name: str) -> str | None:
    """호출이 허용되면 None, 초과면 안내용 에러 JSON을 돌려준다."""
    if limiter.allow(name):        # 허용되면 통과(내부에 이번 호출 기록됨)
        return None
    return json.dumps(
        {"error": f"요청이 너무 잦습니다. 잠시 후 다시 시도하세요: {name}"},
        ensure_ascii=False,
    )
```

`_handle_tool_call`에서 실행 **전에** 빈도를 확인합니다.

```python
    async def _handle_tool_call(self, fc: dict) -> None:
        # 🛡️ 빈도 제한: 초과면 실행하지 않고 안내만 돌려준다.
        denied = rate_limit_error(self._limiter, fc["name"])
        if denied is not None:
            await self._session.send_tool_result(call_id=fc["call_id"], output=denied)
            await self._session.request_response()
            return
        # 통과 시에만 실제 실행(9교시 그대로).
        output = run_tool(fc["name"], fc["arguments"])
        print(f"\n[도구 실행] {fc['name']}({fc['arguments']}) → {output}", flush=True)
        await self._session.send_tool_result(call_id=fc["call_id"], output=output)
        await self._session.request_response()
```

> 💡 **왜 핸들러에서?** 제한기는 "이 세션에서 최근 몇 번" 이라는 상태를 세션 수명 동안 유지해야 합니다. 세션을 쥔 핸들러가 제한기를 소유하는 게 자연스럽습니다. 판단 규칙(`RateLimiter`)은 도메인 순수 코드라 따로 테스트했습니다.

## 📖 용어 사전 (이 교시 신규)

- **정책 가드레일(policy guardrail)**: 형식이 맞아도 "허용된 요청인가"를 정책으로 판단해 거르는 층.
- **허용 목록(allowlist)**: 미리 정한 값만 통과시키는 방어(지원 통화 등).
- **빈도 제한(rate limiting)**: 일정 시간 창 안의 호출 수를 제한해 남용·과부하를 막는 것.
- **창(window)**: 빈도를 세는 시간 구간(예: 최근 10초).
- **상태 있는/없는(stateful/stateless)**: 과거 기록을 기억해야 하는 검사 vs 입력만으로 끝나는 검사.
- **정규화(normalize)**: 비교 전에 값의 모양을 통일하는 것(대소문자·공백 정리 등).
- **`time.monotonic`**: 뒤로 가지 않는(단조 증가) 시계. 경과 시간 측정에 적합.
- **의존성 주입(DI)로 시계 주입**: 현재 시각 함수를 밖에서 넣어 시간 의존 코드를 테스트 가능하게 만드는 것.
